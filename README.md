# 小红书笔记 × 评论 数据分析（只读看板）

把**公开数据集**上的 65,097 条真实评论与 1,582 篇笔记，做成一个可交互的分析看板。

> ⚠️ **这是只读展示版。** 本页不采集任何数据、不发起任何对小红书的请求，
> 全部数据来自公开数据集 + 已经跑完的离线分析结果。原因见下方「为什么不做实时采集」。

---

## 五个页面

| 页面 | 内容 |
|---|---|
| **总览** | 核心指标、数据来源、时间跨度 |
| **全库洞察** | 情感结构、垂类净值排行、时间趋势、发布时段热力、地域分布、热词 |
| **评论构成** | 按**互动意图**（求资源 / 实质讨论 / 情感回应 / 极短点评 / 纯表情）拆分评论区，而不是只按情感 |
| **单篇报告** | 挑一篇笔记，看它的指标、情感、构成、评论原文 |
| **方法与合规** | 完整工作流、情感模型的人工标注校验、合规边界 |

## 为什么不做实时采集

实时采集需要 Playwright 启动**真实浏览器**，并且要**人工扫码登录**。
在无头云端容器里这两件事都做不到：

| 需求 | 在云端 |
|---|---|
| 真实浏览器进程 | ✗ 容器里没有桌面浏览器，装 Chromium 也吃满内存 |
| 扫码登录的可见窗口 | ✗ 二维码在远端容器里，没人看得见那个窗口 |
| 登录态持久化 | ✗ 文件系统是临时的，重启就清空 |
| 能过风控的 IP | ✗ 机房 IP 会被风控标记 |
| 分钟级长驻任务 | ✗ Streamlit 每次交互都重跑脚本，且有请求超时 |

更关键的是**合规**：把采集能力挂成公开 URL，等于让任何人都能拿部署者的
账号身份去爬取，性质就从「个人研究」变成了「对外提供爬取服务」。
所以采集功能保留在**本地版**，云端只放结果。

## 数据处理说明

- **昵称已脱敏**：统一打码为「前两字 + \*\*\*」，在预处理阶段完成
- **不转载他人图片**：单篇报告里的图片墙用占位块 + 数量说明，不放真实用户拍摄的照片
- 原始数据编码为 GB18030（非 UTF-8），预处理时已转换

## 情感分析

自建领域词典 + 位置上下文规则（否定 / 程度 / 弱化），**可解释**、零模型依赖。
准确率是在**与调参集无重叠的留出集**上测的：

| 数据集 | 准确率 | 多数类基线 |
|---|---|---|
| 开发集（调参用） | 96.7% | 48.3% |
| **留出集（对外结论）** | **86.7%** | 48.3% |

已知短板：**负面召回偏低**。讽刺、反语、以及不出现明显情绪词的负面叙事会漏判 ——
纯词典法的天花板就在这里。
